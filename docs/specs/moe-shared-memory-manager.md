# 单实例 MoE 内存压力控制规格

## 当前范围

2026-10-27，用户要求只考虑单个运行中的 Splash 实例。
本规格替代原跨实例共享配额设计，取消协调者选举、公平调拨和故障接任。
同一实例内的自动专家缓存与自动 PLE 仍由一个压力控制器统一约束。
其他应用和其他进程只作为系统内存压力来源。

单实例实现与验收连续推进。2026-10-27 补充要求：Warning 下也按真实余量缩容、保持或恢复。
历史测试、原始权重、转换产物和旧构建全部保留，旧结果不自动算作新路径通过。

## 问题陈述

用户运行一个 MoE 模型时，希望缓存随系统内存状况收缩和恢复。
固定的全局预算仍有效，专家缓存比例由真实模型布局计算。
macOS 的已用百分比、压缩内存、交换空间和可回收余量口径不同，不能用一个百分比猜缓存容量。

系统响应优先于推理吞吐量。新控制器只调整自动存储，保留模型执行下限。
系统压力升高时实际归还存储；余量恢复后逐块增长。

## 配置与兼容性

- `--moe-memory-pressure off|on` 默认 `off`。开启后仅启用当前实例的本地压力控制。
- `--host-memory-reserve auto|SIZE` 设置本实例的系统预留目标。手动值要求开启压力控制。
- 只调整 `--expert-memory auto`；固定专家预算和全驻留要求保持原语义。
- 自动 PLE 纳入本实例的自动存储总配额，手动 PLE 大小与全驻留要求保持固定并准确计费。
- 保留 `--max-memory`、`--expert-ple-memory` 和原 static／adaptive 比例策略的上限语义。
- Dense、不可调整的专家布局、固定专家预算与开启压力控制冲突时明确报错。
- 关闭时保留原布局及必要的系统保护，不增加自动伸缩行为。所有配置使用启动参数，不引入环境变量。

## 模型边界与记账

按实际权重格式计算专家全容量、执行下限、各格式组块大小和辅助存储。
专家容量占比以可容纳的路由专家权重字节数为分子，辅助开销、驻留比例和命中率分别报告。
算法不绑定特定模型名、激活参数比例或固定 GiB 数值。

```text
自动存储上限 = min(模型允许的全容量,
                  用户专家／PLE 上限,
                  本实例全局上限 − 非自动存储必需预算)
```

非自动必需预算包含其他权重、drafter、固定 PLE、工作区、活跃 KV／状态和运行预留。
配置上限、当前配额、实际分配、增长预留及可释放量分别记账，专家和 PLE 不与实例总账重复相加。
本地 charge 中的未跟踪开销预留与尚未完成的增长预留分别报告。
Metal 预算不等于严格进程 RSS 上限；进程物理足迹独立观察。

## 本地增长准入

在大权重分配前建立本地预算与必需阶段上界，覆盖启动、运行、自动缓存增长和空闲恢复。
所有受管理的正向分配先预留，再执行，最后按成功、失败、部分成功或取消核对实际量。
同一分配不能重复预留或重复归还，未知阶段不能以零预算放行。
临时峰值、主机存储和 Metal 缓冲均计入本地边界，不只包住就绪后的专家缓存。

本地硬上限、系统保护和驱动拒绝始终有效。
必需分配与可选缓存增长分开，必需 KV／状态和恢复至执行下限不受可选增长节流限制。
所有请求继续使用原有资源等待期限、错误语义和状态提交规则。

单实例路径不得创建或访问跨进程协调组、Unix socket、领导锁、心跳或共享账本。
不得等待协议兼容、协调者或其他 Splash 实例确认。
旧全局协调目录缺失、损坏或包含旧协议时，都不能阻止本地模式启动。
本轮不迁移、修复或删除旧全局协调记录。

## 系统观测与压力策略

复用现有系统压力事件和 500 ms 兜底采样。
系统预留 auto 取物理内存的 7%，限制在 2 GiB～7 GiB；手动值替换这个基础目标。
预警余量为 1 GiB，恢复余量为 2 GiB，均按本实例使用。

系统 spare 已反映当前占用，不再扣除一遍本实例的实际分配。
只对尚未落实或未完成核对的本地增长保留保守额度。
spare 含可回收页和压缩信用，是估计值，不是保证可用的物理内存。

```text
可选增长余量估计 = max(0, spare − 基础预留 − 1 GiB − 未核对增长预留)
待回收缺口估计 = max(0, 基础预留 + 1 GiB − spare)
恢复门槛 = 基础预留 + 2 GiB
```

冷启动先分配当前模型的可执行下限。
Normal 和 Warning 均按真实余量判断。低于基础预留加 1 GiB 时，按缺口和真实块缩容。
处于预警与恢复门槛之间时保持容量；达到恢复门槛后进入稳定观察。
Critical 时在 GPU 安全点尝试降到模型下限；仍不足则暂停新请求启动，沿用原等待期限。
遥测未知时停止可选增长，不把未知解释为需要释放全部缓存；有效 Critical 信号仍执行保护。

Normal 或 Warning 且达到恢复门槛连续稳定 30 秒后，本实例每 5 秒最多增加一个真实自动存储块。
专家块与 PLE 块共用这一个本地增长节流规则。
实际新增几个块就计几个，不能把整体 resize 一次调用视为只增长一块。
增长完成、核对实际量并取得后续有效样本后，才释放该次预留，并从该完成点计算下一次 5 秒冷却。
Critical、未知压力、余量跌破恢复门槛、分配失败或遥测失效时重新观察，重试不能额外授块。
重复 Warning 样本不重置合格的稳定期；短暂不安全事件也必须使旧增长许可失效。
分配与块提交前重新检查真实压力、余量和本地上限，状态继续如实报告 Warning。

缩容前停止并等待相关预读，保持已绑定地址和专家映射有效。
收缩释放的额度不提高 KV／状态缓存扩容上限，不改变全局预算、上下文、量化或采样。

## 专家与 PLE

本地压力控制器决定自动专家和自动 PLE 的总配额，原比例策略只在该配额内工作。
专家让出的空间不能由 PLE 立即补满；实例内转移先确认实际释放，再通过本地准入增长。
固定 PLE 按实际保留量计费，不受自动调整，预算不足时明确等待或拒绝。
没有 PLE 的模型只调整专家缓存，不要求启用 PLE 自适应策略。

## 释放和恢复

公开释放接口及空闲释放继续可用。
下一请求先恢复固定部分，再按当时余量选专家目标，计入仍保留的 PLE 和辅助表。
申请 payload 前选容量，不先恢复全部旧缓存再缩小。
目标块、staging 和必需专家全部就绪后才继续推理；失败或取消保留可重试状态。
超过执行下限的可选恢复部分继续遵守本地 30 秒／5 秒规则。

## 状态契约

启动清单和 `/status` 明确显示 `off` 或本地压力控制模式。
报告压力级别、决策原因、配置上限、模型下限、当前配额、实际量、增长预留、已释放量、稳定期和冷却。
报告专家容量占比、驻留比例、命中率、系统预留及余量估计，区分 Metal 分配与进程物理足迹。
跨实例角色、组、领导任期、心跳和调拨字段退出当前契约，相关 schema、启动渲染和测试同步调整。
不能把“已无协调者”伪装成协调就绪，也不能因旧协议记录而显示本地功能不可用。

## 验收标准

- [ ] A1：默认关闭和手动预算兼容；参数冲突明确失败，现有启动器默认值不变。
- [ ] A2：按不同模型、格式和混合量化计算下限、全容量、块增量及容量比例。
- [ ] A3：本地预留覆盖启动、运行、KV／状态、自动增长和恢复，临时峰值及部分失败无漏记或重复记账。
- [ ] A4：本地模式完全不依赖 IPC、选举、共享账本或旧全局协调目录，相关旧专用调用与测试移除。
- [ ] A5：Warning 有缺口才继续缩容；Critical、遥测未知、到达下限、无进展和原等待期限均有确定性用例。
- [ ] A6：Normal／Warning 在合格余量下的 29,999／30,000 ms、增长后 4,999／5,000 ms、真实多块调用、失败重试及压力反复均保持本地节流。
- [ ] A7：专家与自动 PLE 总配额联动，手动 PLE 保持固定，没有 PLE 的模型正常工作。
- [ ] A8：实际释放后能以较小容量恢复；保留 PLE 不重复计费，失败不暴露半恢复状态。
- [ ] A9：行／专家映射、算子数值、完整提交状态及生成对照维持原标准，保留首处分歧。
- [ ] A10：回收前后全局及 KV／状态上限、量化、采样和 token 提交规则保持不变。
- [ ] A11：公开清单和状态真实反映本地模式、实际分配、压力与冷却，不残留误导性的协调角色。
- [ ] A12：受影响回归及仓库必需门禁覆盖最终源码候选，保留命令、构建身份、日志、真实退出码和资源清理证据。
- [ ] A13：本轮实模只用 Tiel、单实例、并发 1，采用明确硬预算；真实 PLE 明确保留未验收，不能从 Tiel 推断通过。
- [ ] A14：使用现有服务边界与原生配置／生命周期入口，不新增生产压力注入接口，不填满整机、不测性能、不放宽原标准。

本地确定性检查先行，再做有界 Tiel 实机正确性验证。
真实 Warning 且余量充足时必须验证逐块增长；余量不足或其他保护阻止增长时如实保留未验收项。
不改报 Normal，不放宽数值、状态、预算或原超时。
性能测试另行安排，旧多实例结果不代替新的单实例验收。
