# Tiel Q4H 并发校验修正

## 原始失败与诊断

冻结版本的并发 2 推理完成两个 16K 输出，原生退出码为 0，事实、长度、冷缓存与内存通过；额外的跨运行 token 比较在第二个请求索引 15 失败，校验驱动退出码为 1。

紧凑检查 `tiel-concurrency-prefix-check.py` 重放原始数据稳定失败。两个真实前缀探针分别在索引 3 和 15 出现分歧，证明同一请求配置并不固定实际执行过程。
调度器 `prefillBudget` 在有并行解码时根据真实成本缩小预填充块，目标 500 ms，最小 64 行。动态探针观察到 512／1024／2048 等块，固定分块对照两次前 32 个 token 完全一致。
固定成本使用显式合成调度估计，只用于诊断；不作为真实性能计时，不进入原性能二进制。

仓库 `model_runtime_oracle_test.mm` 已区分不同图：相同 B4 图内的相同输入必须有相同决策；B1 使用不同图，其 token 决策是诊断数据。共享头比较也要求参考命令具有相同矩阵行数。
原性能脚本把“请求参数相同”误当作“所有实际命令相同”，新增的全并发逐 token 断言因此比较了不同图。

## 保留的数值与业务门禁

生产库、算子、metallib、权重及性能二进制保持冻结。
对真实 Tiel MoE 与 Q4H 运行原有冷图用例，原生退出码为 0：非有限值隔离通过，分块卷积／循环状态余弦均为 1.0，同图四路 token 一致，交换顺序与修改邻请求时分数相对误差均为 0。
原分数容差仍为 1e-3，原状态余弦仍要求大于 0.999，原同图 token 精确断言保留。

单请求继续逐 token 严格核对；并发动态图的真实 token 分歧完整记录，并绑定数值证据。没有把不同 token 标成匹配，也没有让事实检查取代数值检查。
源码、权重、Q4H、block=8、splits=8、ANE 关闭、功能关闭、冷请求和 greedy 适用范围均核验；超出范围不沿用证据。
10 项回归检查通过，包括原并发失败数据重放、单请求错误、原容差边界、数值证据失败、源码／权重变化及错误工作负载。

## 已知的独立失败

完整 oracle 在“采样＋快照恢复后重放一个 token”的用例失败，原生退出码为 1。该完整结果未记为通过，日志和失败保留；原因尚未进一步定位。
当前性能请求固定 cold_requests=true、temperature=0，不执行该采样恢复用例。本次通过的范围是原有冷图检查，不能据此宣称完整 oracle 或所有模型功能通过。
首次数值入口构建缺少两个官方测试插桩对象，链接退出码为 1；按仓库规则补齐冻结对象后构建通过。构建原错误也保留。

## 恢复测量

原 16 个合格样本保留；原并发 2 的真实推理数据经完整业务校验和正确图比较规则重新收录，不重跑已经完成且无外部负载的推理。
恢复时共有 17 个有效逻辑样本，继续剩余 46 批。原失败记录、原始输出及不匹配字段保留。Q4H 标准参数未变。
当前目录为 `build/tiel-miniplus-q4h-output16k-sweep-v4`；空闲 30 秒、外部负载检测及后续配对仍启用。
