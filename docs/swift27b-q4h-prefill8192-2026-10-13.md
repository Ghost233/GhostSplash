# Swift 27B：追加 8192 prefill 分块对照

8192 分块追加 3 轮有效性能运行，控制器真实退出码为 0。与之前 512／2048／4096 的各 3 轮合计 12 次。A2048 仍为选定基准，本轮不修改启动参数。

同一份混合 GGUF、同一份输入 token IDs 和排名文件，实际输入 8192、输出 4096；Q4H、ANE share=0.5／阈值 512、DFlash2 block=8、splits=16、并发1、上下文容量131072、lookup和compact开启、greedy、冷请求和忽略EOS保持不变。

全局块预算为8192；引擎保留最后32行尾块，所以正式请求真实分块为 `[8160, 32]`。预热使用最大8192行。集成attention校验分别覆盖最大8192行、实际8160行和32行尾块，使用原max_abs<0.02、cosine>0.9995，检查页写入和canary。

沿用ANE编译修复的规模控制，8192构建采用512行函数间隔，共16个函数，覆盖512～8192。三轮实际ANE均开启，share=0.5／阈值512，每轮64次调用。原ANE贡献RMS上限10%不变；同配置完整4096输出token重复一致，事实、参数、冷请求和内存账本均通过。

加载、ANE准备、集成数值检查和预热排除在正式请求耗时之外，没有独立的完整生成正确性轮次。已知外部活动推理与benchmark监控记录为空，但不能排除桌面负载与设备波动。

速度和耗时取三轮中位数，内存取最大峰值。8192属于后续独立批次，跨批次小幅速度差异还需要配对确认，不能全部归因于块预算。跨配置首次token分歧单独保存。

8192 三轮的全部 4096 个输出 token 与 A2048 相同。相对 4096 的总耗时中位数只减少约 0.34 秒（0.56%），设备分配峰值增加约 1.51 GiB；这轮未证明 8192 有额外 prefill 收益，A2048 仍保留为选定基准。首轮冷 ANE 准备约 78.7 秒，单独保存在原始启动计时中。
