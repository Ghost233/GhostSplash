# Swift 27B：lookup 与 compact 参数微调

五组各 3 次性能运行，有效完成 15／15，控制器真实退出码为 0。固定原混合 GGUF 与 DFlash2、原输入 token IDs 和排名，8K 输入、实际 4096 输出、Q4H、全局分块2048、splits16、ANE share0.5／阈值512、block8、并发1、容量131072、greedy与冷请求。

新增启动参数 `SPLASH_PROMPT_LOOKUP_MIN_MATCH`（默认2，支持2／3／4）和 `SPLASH_COMPACT_DRAFT_CAPACITY`（默认98304，256的倍数，范围512～98304）。原功能开关保持独立，关闭时不读取对应覆盖参数。罕见token比例1%和动态补充256的回退规则不变。

每次只改变一项：A=下限2／容量98304；L3=下限3；L4=下限4；C64=容量65536；C32=容量32768。正序、反序、旋转顺序各一轮，加载、ANE准备、数值检查和预热排除在正式请求耗时之外。

## 校验与证据

原attention标量界限max_abs<0.02、cosine>0.9995，ANE贡献RMS上限10%不变。compact检查保留原量化plane字节、选中logits逐位一致性、FP64误差界限、padding和DFlash2映射。真实参数、实际ANE256次调用、事实、强制长度、冷请求、内存账本和每配置完整输出重复均通过。A与历史基准全部4096个输出token相同。

生产AIR和原生产metallib保持不变；检查库使用仓库现有production-and-test入口附加原字节检查需要的测试函数。原缺失测试函数和复制执行权限的启动失败保留归档，未产生有效性能样本。

已知活动推理／benchmark监控没有重叠，不能排除桌面负载和设备波动。源码检查、完整CPU检查及全部原生工具编译通过。GPU数值与完整生成校验并入15次性能运行，没有独立完整输出正确性阶段。本轮范围为C1。

五组的全部 4096 个输出 token 彼此相同，且都与历史 A 一致。L3 的 decode 中位数提高约 2.37%，总耗时减少 1.67%，值得配对复核；L4 总耗时改善仅 0.24%，收益未证明稳定。C64／C32 额外缓冲分别减少 90.125／180.25 MiB，但总耗时增加 1.80%／1.42%，每轮均记录 3 次 compact 回退。现阶段保留 A，L3 作为候选，原默认值不自动改动。
