# Tiel MiniPlus：五种 KV 格式三轮对照

## 固定条件

主模型、drafter、源码、输入和采样均与上一轮一致。只改变 KV，测 INT8、BF16、Q4_0、Q4_0 unrotated 和 Q4H。

固定 32,768 实际输入、实际输出 512／2,048 tokens、splits=8、DFlash2 block=8、并发 1。ANE、lookup、compact 和 fast top-k 均关闭。greedy、ignore_eos=true、冷请求，上下文容量 36,864 tokens，内存预算 32 GiB。每次启动使用固定预热，模型加载和预热不计入请求耗时。

每格式、每输出重复 3 轮，共 30 次，执行 21.5 分钟。三轮中的平均格式出场位置均为第 3 位；长短输出顺序交替。全部样本保留，没有按速度重跑或剔除。

| 轮次 | 格式顺序 |
| --- | --- |
| 1 | INT8 → BF16 → Q4_0 → Q4_0 unrotated → Q4H |
| 2 | Q4_0 → Q4_0 unrotated → Q4H → INT8 → BF16 |
| 3 | Q4H → BF16 → Q4_0 unrotated → INT8 → Q4_0 |

## 结果和建议

BF16 的 prefill 中位数最高，512 输出总耗时中位数最低；INT8 的 2,048 输出 decode 和总耗时中位数最好。三种 Q4 中，Q4H 在两个输出长度下的总耗时中位数均最低。

BF16 与 INT8 的小幅总耗时差异没有稳定的逐轮方向。BF16 的短输出和长输出均有 2／3 轮总耗时高于同轮 INT8。各组中位数比较与同轮比值的中位数是不同统计量，速度波动时可能给出不同方向。因此，本轮不能证明 BF16 稳定优于 INT8。

BF16 的 device 峰值比 INT8 多 280 MiB。Q4_0 和 unrotated 比 INT8 少 113.75 MiB；Q4H 少 158.75 MiB。共用基准暂时保留 INT8，BF16 作为接近的备选，Q4H 保留为低内存候选。

长输出草稿接受率为 INT8 73.84%、BF16 65.65%、Q4_0 69.79%、unrotated 61.90% 和 Q4H 44.58%。这些格式的输出轨迹不同，decode 差异包含接受率与生成内容的影响。不能仅用事实通过来判断数值误差或回答质量相同。

## 校验与结果范围

全部 30 次原生运行退出码为 0，输入／输出长度、事实、同 KV 冻结输出和内存账本校验通过。各格式的首次分歧、输出哈希和草稿接受数量均保留。不同 KV 的输出轨迹可以不同，因此 decode 差异同时包含生成内容和草稿接受率的影响，不能等同于单个算子的耗时差。

本轮未改生产算子。沿用已冻结的原生入口及之前的构建与正确性门禁。主模型 GGUF 权重量化固定；本轮的三种 Q4、INT8、BF16 均指 KV 存储格式。

按用户授权接受后台波动，检测到后台服务忙的样本数为 3。原始负载采样保留，结果不能视为隔离环境下的稳定上限。

结束时重新核对源码、构建产物与原始权重 SHA-256，均一致。测试引擎和驱动已退出，没有停止其他服务。
