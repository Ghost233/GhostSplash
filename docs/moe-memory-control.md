# 单实例 MoE 内存压力控制

目标是在一个 Splash 实例内，按系统压力调整自动专家与自动 PLE 缓存。
2026-10-27 已按用户要求改为单实例设计，相关任务见[工单与 PR 计划](plans/moe-shared-memory-tickets.md)。

单实例实现与验收连续推进，最终通过情况以当前候选的验证记录为准。
Warning 是支持的运行状态，是否调整缓存取决于真实余量。

## 参数目标

在原服务命令中显式添加：

```text
--expert-memory auto --moe-memory-pressure on --host-memory-reserve auto
```

| 参数 | 默认值 | 单实例语义 |
| --- | --- | --- |
| `--moe-memory-pressure off\|on` | `off` | 仅控制当前实例的自动存储。 |
| `--host-memory-reserve auto\|SIZE` | `auto` | 本实例的系统余量目标；手动值要求开启压力控制。 |
| `--expert-memory auto` | `auto` | 使用可调整的专家布局，固定专家预算保持原语义。 |

现有全局预算、专家／PLE 上限和 static／adaptive 比例策略继续有效。
自动 PLE 与专家受同一本地自动存储总配额约束；手动 PLE 和全驻留要求保持固定。
Dense、不可调整的布局和固定专家预算与开启压力控制冲突时明确报错。
配置继续使用启动参数，现有启动器默认值保持不变。

## 压力策略

系统预留 auto 为物理内存的 7%，限制在 2 GiB～7 GiB。
Normal 和 Warning 均以基础预留加 1 GiB 计算缺口，恢复门槛为基础预留加 2 GiB。
spare 是包含可回收页和压缩信用的估计值，不能再扣除一遍本实例实际量。

| 状态 | 行为 |
| --- | --- |
| 冷启动 | 从当前模型的可执行下限起步。 |
| Warning | 按缺口回收真实块；中间余量保持容量；达到恢复门槛并稳定 30 秒后，每 5 秒最多增长一个真实块。 |
| Critical | 在安全点尝试降到模型下限，仍不足则暂停新请求启动并沿用原等待期限。 |
| Normal | 采用相同余量门槛与恢复节流规则。 |
| 遥测未知 | 暂停可选增长，不把未知解释为全部缓存都要释放。 |

专家和 PLE 共用一个本地增长节流规则，按实际新增块数计数。
重复 Warning 不重置合格稳定期。Critical、未知压力、低余量或失败使旧许可失效。
分配与块提交前复查真实压力及余量，状态继续如实报告 Warning。
必需分配及恢复到执行下限沿用本地准入，不受可选增长限速误限。
每次分配先预留，再核对实际成功、部分成功、失败或取消。

缩容前停止必要预读，在 GPU 安全点保持地址表、专家映射及提交状态有效。
回收额度不提高 KV／状态上限，不改变全局预算、上下文、量化或采样。
空闲恢复时先计入固定部分、保留的 PLE 和辅助存储，再选择较小目标。

## 状态目标

启动清单和 `/status` 应显示本地控制模式、压力、等待原因、稳定期与冷却。
同时报告模型下限、配置上限、当前配额、实际分配、增长预留和实际释放量。
`normal_stable_milliseconds` 保留旧字段名，表示 Normal 或 Warning 下恢复余量已连续合格的时长。
可选 MoE 增长的等待原因见 `automatic_growth_reason`；观测期使用 `headroom_observation`。
通用 `host_growth_allowed` 保留原系统保护语义，不能单独用它判断 MoE 是否允许恢复。
容量比例、驻留比例、命中率、Metal 分配与进程物理足迹分别展示。
跨实例角色、组、领导任期、心跳和调拨字段退出当前状态契约。

比较释放前后的引擎分配量，使用 `memory_actual.allocated_bytes`。
`memory_audit` 若标记为 `startup_warmup`，记录的是启动阶段，不随之后的释放更新。

改造后的本地模式不创建或读取全局协调目录，旧协议或缺失账本不得阻止启动。
旧记录保留，本轮不执行账本恢复、迁移或删除。

## 验收状态

单实例路径已通过 16 项有界 Metal 资源检查，以及 Tiel 的严格数值与公开服务检查。
Tiel 在真实 Warning 下完成增长、缩容、重新增长、释放和较小容量恢复，原校验标准与期限保持不变。
公开服务分别验证开启本地控制和默认关闭，原生进程清理退出码均为 0。
源码、原生构建、CPU、Sanitizer 和构建身份检查退出码为 0。
这些结果绑定已记录的工作区候选；精确提交的构建身份和最终审查另行核对。
本轮真实模型只用 Tiel、单实例、并发 1；真实 PLE 项保留未验收。
实模采用 8 GiB 硬预算、8 个输入 token 和 16 个实际输出 token。
确定性检查使用既有注入入口，不填满整机、不放宽数值或超时标准、不运行性能测试。

完整要求见[规格](specs/moe-shared-memory-manager.md)和[单实例决策](adr/0005-single-instance-memory-control.md)。
