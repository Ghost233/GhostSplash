# Tiel MiniPlus：16K 输出三种 KV 三轮复测

## 固定条件

主模型、drafter、输入和采样均与此前一致。测试 INT8、BF16 和 Q4H，每种格式重复 3 轮，共 9 次。

固定 32,768 实际输入和 16,384 实际输出，上下文容量 131,072 tokens。实际轨迹使用 49,152 tokens，容量上限不等于输入长度。splits=8、DFlash2 block=8、并发 1，ANE、lookup、compact 和 fast top-k 均关闭。greedy、ignore_eos=true、冷请求；内存预算仍为 32 GiB。

本轮复用与上一轮字节一致的原生入口和每 2048 tokens 的进度日志，未重新编译。生产引擎、算子、metallib、库、输入和参数均未改变，三种格式使用同一入口。

所有 9 次运行的完整 16K 轨迹均与上一轮同 KV 的冻结输出逐 token 核对；前 2048 tokens 继续与更早的冻结输出核对。事实、精确输出长度和内存标准不变。

运行约 16.8 分钟。格式每轮轮换，每种格式分别处于第一、第二和第三位。模型加载和固定预热不计入请求耗时，全部波动样本保留。

| 轮次 | 格式顺序 |
| --- | --- |
| 1 | INT8 → BF16 → Q4H |
| 2 | BF16 → Q4H → INT8 |
| 3 | Q4H → INT8 → BF16 |

## 结果和建议

本轮 INT8 的 decode 中位数为 200.1 tokens/s，总耗时为 98.25 秒。BF16 和 Q4H 的 decode 中位数为 185.6 和 185.5 tokens/s，总耗时为 104.26 和 104.13 秒。三种格式的 prefill 中位数在 2074.7～2087.9 tokens/s，差距约 0.64%。

INT8 在 3／3 轮中比 BF16 decode 更快，与 Q4H 对比则有 2／3 轮更快。共同基准继续暂时保留 INT8。Q4H 比 INT8 少 321.25 MiB，BF16 比 INT8 多 422.5 MiB，内存峰值与上一轮完全一致。

本轮 3／9 次记录到后台服务忙，上轮为 5／9 次。本轮 decode 范围为 INT8 186.4～205.6、BF16 185.2～190.4、Q4H 181.5～200.7 tokens/s。上轮 INT8 的范围为 145.4～235.5，Q4H 为 96.6～197.2。波动缩小，但当前对照仍接受后台负载，不能将小幅差异认定为隔离条件下的稳定排名。

与上一轮相比，prefill 中位数提高 7.63%～23.55%，decode 中位数变化为 INT8 +1.33%、BF16 −1.00%、Q4H −1.08%。两轮的输出和草稿数量完全一致，速度变化不能解释为生成了不同内容。当前数据支持三种格式的 prefill 接近，不支持长期固定的较大 prefill 差距。

全部 9 次原生运行退出码为 0，完整 16K 输出与上一轮同 KV 逐 token 一致，旧 2048 前缀、事实、长度和内存校验全部通过。源码、原生入口和权重身份一致，测试资源已释放。

## 校验与结果范围

全部 9 次原生运行退出码为 0，输入／输出长度、事实、同 KV 冻结输出和内存账本校验通过。各格式的首次分歧、输出哈希和草稿接受数量均保留。不同 KV 的输出轨迹可以不同，因此 decode 差异同时包含生成内容和草稿接受率的影响，不能等同于单个算子的耗时差。

本轮未改生产算子。沿用已冻结的原生入口及之前的构建与正确性门禁。主模型 GGUF 权重量化固定；本轮的 INT8、BF16 和 Q4H 均指 KV 存储格式。

结束时重新核对源码、构建产物与原始权重 SHA-256，均一致。测试引擎和驱动已退出，没有停止其他服务。
