# Tiel MiniPlus：16K 输出三种 KV 三轮对照

## 固定条件

主模型、drafter、输入和采样均与此前一致。测试 INT8、BF16 和 Q4H，每种格式重复 3 轮，共 9 次。

固定 32,768 实际输入和 16,384 实际输出，上下文容量 131,072 tokens。实际轨迹使用 49,152 tokens，容量上限不等于输入长度。splits=8、DFlash2 block=8、并发 1，ANE、lookup、compact 和 fast top-k 均关闭。greedy、ignore_eos=true、冷请求；内存预算仍为 32 GiB。

本轮只扩展独立测试入口的允许输出长度，并加入每 2048 tokens 的轻量进度日志。生产引擎、算子、metallib 和库未改。所有格式使用同一入口。首次构建遗漏身份头文件的错误已修复，原始错误及构建命令保留。无效的 16,385 输出负例按原标准拒绝，不加载模型。

每种格式第一轮建立完整 16K 参考轨迹；后两轮逐 token 核对。同时，所有运行的前 2048 tokens 与此前同 KV 的冻结输出核对。事实、精确输出长度和内存标准不变。

运行约 22.1 分钟。格式每轮轮换，每种格式分别处于第一、第二和第三位。模型加载和固定预热不计入请求耗时，全部波动样本保留。

| 轮次 | 格式顺序 |
| --- | --- |
| 1 | INT8 → BF16 → Q4H |
| 2 | BF16 → Q4H → INT8 |
| 3 | Q4H → INT8 → BF16 |

## 结果和建议

16K 输出下，INT8 的 decode 中位数为 197.5 tokens/s、总耗时为 100.62 秒。BF16 和 Q4H 的 decode 中位数都约为 187.5 tokens/s，总耗时分别为 104.70 和 105.13 秒。BF16 的 prefill 中位数最高。

INT8 在三轮中均比同轮 Q4H decode 更快；与 BF16 对比则是 2／3 轮更快。9 次运行中有 5 次记录到后台服务忙。INT8 的 decode 范围为 145.4～235.5 tokens/s，Q4H 为 96.6～197.2 tokens/s。当前条件下，共同基准暂时保留 INT8；这些结果不能确定隔离负载下的稳定排名。

Q4H 的 device 峰值比 INT8 少 321.25 MiB，BF16 则多 422.5 MiB。容量设为 131,072，但实际轨迹只使用 32,768 输入与 16,384 输出；本轮没有测量 128K 实际输入。

三种格式的长输出接受率升为 INT8 95.91%、BF16 92.15% 和 Q4H 87.74%。速度只代表当前输入和强制 16K 生成轨迹，不能直接推广到自然结束或不同任务。9 次都没有生成 tokenizer EOS 集合中的 token，但仍可能出现内容重复。

全部 9 次退出码为 0，长度、事实、内存账本、同 KV 的完整 16K 重复轨迹与此前的 2048 token 前缀均通过。不同格式间的轨迹和接受率仍有差别，不能用事实通过代替算子误差或回答质量比较。

## 校验与结果范围

全部 9 次原生运行退出码为 0，输入／输出长度、事实、同 KV 冻结输出和内存账本校验通过。各格式的首次分歧、输出哈希和草稿接受数量均保留。不同 KV 的输出轨迹可以不同，因此 decode 差异同时包含生成内容和草稿接受率的影响，不能等同于单个算子的耗时差。

本轮未改生产算子。复用同一生产引擎及之前的构建与正确性门禁，本轮扩展入口独立编译并在测量前冻结。主模型 GGUF 权重量化固定；本轮的 INT8、BF16 和 Q4H 均指 KV 存储格式。

按用户授权接受后台波动，检测到后台服务忙的样本数为 5。原始负载采样保留，结果不能视为隔离环境下的稳定上限。

结束时重新核对源码、构建产物与原始权重 SHA-256，均一致。测试引擎和驱动已退出，没有停止其他服务。
