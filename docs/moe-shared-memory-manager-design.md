# 单实例 MoE 自动存储管理设计

2026-10-27，用户将范围调整为一个运行中的 Splash 实例。
当前设计采用实例内压力控制器，详见 [ADR 0005](adr/0005-single-instance-memory-control.md)。
正式规格见[单实例规格](specs/moe-shared-memory-manager.md)，任务见[工单计划](plans/moe-shared-memory-tickets.md)。

单实例实现与验收连续推进。Warning 下按真实余量决定缩容、保持或恢复。

## 责任划分

系统观测提供压力事件和余量估计，本地控制器计算本实例的目标配额。
模型存储按真实布局给出执行下限、全容量、单块计划和实际分配。
本地准入覆盖每次正向分配，既有推理运行时负责安全点、请求期限和状态提交。

一个控制器管理自动专家与自动 PLE 的总额，原比例策略只在当前总额内调整。
固定 PLE 与其他必需分配先计入预算，没有 PLE 的模型沿用专家路径。
其他进程只影响系统采样，不参与本实例的授权与生命周期。

## 容量和系统余量

自动存储上限取模型全容量、用户存储上限及全局剩余预算的最小值。
全局预算先计入其他权重、drafter、固定 PLE、工作区、KV／状态和运行预留。
容量比例按路由专家权重字节计算，辅助开销、驻留比例和命中率分别报告。

系统 spare 已包含当前分配的影响，不能再次扣除本实例实际量。
基础预留 auto 为物理内存的 7%，限制在 2 GiB～7 GiB；手动值替换该目标。
预警与恢复余量分别为 1 GiB、2 GiB，系统估计值不构成物理内存保证。

## 本地事务

正向分配前确定用途、必需／可选分类及峰值上界，先预留后执行。
成功、失败、部分成功或取消都按实际分配核对，未完成额度保持保守记账。
控制器建立在大权重分配前，覆盖启动、运行及恢复，不使用远端授权或持久化协议账本。
本地上限、Critical 保护和驱动拒绝始终有效。

冷启动先给执行下限；请求必需增长与恢复到下限沿用原准入和等待期限。
缩容等待必要预读结束，并在 GPU 安全点保持地址表和已提交状态有效。

## 压力与恢复

Normal 和 Warning 采用相同余量门槛。低于基础预留加 1 GiB 时按缺口缩容，
预警与恢复门槛之间保持容量，达到基础预留加 2 GiB 后开始稳定观察。
Critical 尝试降到下限，仍不足则暂停新请求启动，沿用原资源等待错误。
遥测未知时冻结可选增长，不推断全部缓存都必须释放。

Normal 或 Warning 达到恢复门槛并稳定 30 秒后，本实例每 5 秒增加至多一个真实专家或 PLE 块。
以实际块计数，分配完成并核对新样本后再推进冷却。
Critical、未知压力、低余量、失败或遥测失效重新观察；重复 Warning 不重置合格稳定期。
短暂不安全事件使旧许可失效，分配与块提交前复查真实观测。
启动与恢复中的可选部分不能绕过规则。
回收量不扩大 KV／状态上限，不改上下文、量化、采样或 token 提交。

## 空闲恢复

先恢复固定部分，计入保留的 PLE 和辅助存储，再选择当前合法的专家目标。
在申请 chunks 前选几何，避免先恢复旧的大缓存再缩小。
必需资源全部恢复后才能服务，失败保持可重试，较高可选目标继续逐块增长。

## 移除旧协调依赖

从本地启动、分配、恢复和状态路径移除共享会话、socket、领导锁、心跳、任期和成员账本。
旧全局协调目录不得被读取，也不得影响启动。旧目录和原始记录保留，不安排修复或迁移。
跨实例专用测试随旧调用移除；单实例预算、映射、数值和恢复回归保留。
公共状态显示本地模式，不能残留协调者就绪或公平调拨等误导状态。

## 验收与交付

单实例确定性测试覆盖余量、Warning／Critical、故障、30 秒／5 秒边界及实际缩扩容。
本轮实机只用 Tiel、并发 1，并保留明确硬预算与真实压力保护；真实 PLE 保留未验收。
维持原数值、状态和超时标准，记录真实退出码，不执行性能或整机压力测试。
旧组件结果可作复用证据，不能直接宣称单实例改造已经通过。
